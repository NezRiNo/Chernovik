# Черновик

**Веб-журнал студенческого творчества Новосибирска.** Публикуйте тексты, стихи, иллюстрации, фотографии и музыку — редакция проверит работу, а читатели смогут её найти, обсудить и поддержать.

[Репозиторий](https://github.com/NezRiNo/Chernovik) · [Сообщить о проблеме](https://github.com/NezRiNo/Chernovik/issues)

---

## Что внутри

- Каталог работ с фильтрами по форме, вузу и тегам
- Публикация и редактирование работ с обложкой и тегами
- Комментарии, реакции и жалобы
- Личный кабинет автора и очередь редакционной проверки
- Демо-режим без подключения базы данных
- Адаптивный интерфейс, светлая и тёмная темы

## Быстрый просмотр

Откройте папку `public` через любой локальный HTTP-сервер:

```bash
cd public
python3 -m http.server 8080
```

Затем перейдите на http://localhost:8080. Без ключей Supabase включается демо-режим. Демо-аккаунты: `mila_writes` и `redaktor`, пароль `demo1234`.

> Демо-режим хранит данные и тестовые пароли только в локальном хранилище браузера. Не используйте в нём реальные пароли и личные данные.

## Запуск с Supabase

1. Создайте проект в [Supabase](https://supabase.com/).
2. Выполните `supabase/schema.sql` в **SQL Editor**.
3. В `public/js/config.js` укажите Project URL и publishable/anon key. **Не добавляйте secret/service_role key во фронтенд.**
4. В Authentication отключите подтверждение Email, так как регистрация использует ник без почты.
5. В **Authentication → URL Configuration** укажите адрес сайта.
6. Зарегистрируйте себя и назначьте роль редактора SQL-командой:

   ```sql
   update public.profiles set role = 'editor' where nick = 'ваш_ник';
   ```

Для существующей базы с тегами выполните миграцию `supabase/migrations/2026-11-work-tags.sql` в SQL Editor. Новые установки получают поле тегов из основной схемы.

## Публикация

Сайт — статический фронтенд без сборки. Публикуйте содержимое `public/` через GitHub Pages, Netlify, Vercel или Cloudflare Pages. Для GitHub Pages выберите **Settings → Pages → GitHub Actions**.

После публикации проверьте регистрацию, вход, отправку и редактирование работы, модерацию, комментарии, реакции, жалобы и удаление аккаунта в отдельной тестовой учётной записи. Секреты Supabase не должны попадать в репозиторий.

## Структура

```
public/                 интерфейс и клиентский код
  css/                  стили и шрифты
  js/app.js             страницы и взаимодействия
  js/data.js            Supabase и демо-режим
  js/config.js          публичная конфигурация проекта
supabase/schema.sql     схема, RLS и хранилище
supabase/migrations/    миграции для существующих баз
```

## Перед открытым запуском

Заполните данные оператора и проверьте юридические тексты в `public/js/config.js`. Проведите тестирование на отдельном проекте Supabase, убедитесь, что RLS включён, а загрузка обложек ограничена нужными типами и размером. Демо-режим предназначен только для знакомства с интерфейсом.
